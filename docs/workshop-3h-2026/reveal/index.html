Lesson 1 Part A + Part B

References create runtime wiring

var api = builder.AddProject<Projects.Bookstore_API>("api");

builder.AddProject<Projects.Bookstore_Web>("web")
    .WithReference(api)
    .WaitFor(api)
    .WithExternalHttpEndpoints();
WithReference
Injects connection/discovery configuration.
WaitFor
Coordinates startup readiness.
External
Marks an endpoint for user access.

Names replace hardcoded ports

client.BaseAddress = new("https+http://api");
  • api matches the AppHost resource name.
  • https+http prefers HTTPS, then falls back to HTTP.
  • Aspire injects the actual endpoints at runtime.
  • Discover ports from the dashboard or aspire describe.

Never teach a dynamic system with copied localhost ports.

Human loop vs agent loop

Human

aspire run --apphost <path>
# Ctrl+C

Foreground output and dashboard.

Agent

aspire start --apphost <path> --isolated
aspire wait api --apphost <path>
aspire describe --format Json
aspire stop --apphost <path>

Background, explicit, structured, bounded.

One model, three deployment verbs

publish

Build model and write target artifacts. Does not install them.

deploy

Build, push, provision, and install/update. Has side effects.

destroy

Remove tracked target resources. Requires deliberate approval.

--list-steps reveals the target pipeline before execution.

Troubleshooting: shortest path to evidence

aspire doctor
aspire ps
aspire describe --format Json
aspire logs api --tail 100
aspire otel traces api --has-error
  • npm: pass the required proxy with --registry
  • unknown URL: read startup output or describe
  • Cosmos cold: wait, stop, restart
  • worktree collision: use --isolated
  • many AppHosts: always pass --apphost
